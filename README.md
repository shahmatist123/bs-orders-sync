# bs-orders-sync

Мини-синхронизатор заявок: забирает `https://test.ooobs.ru/api/orders`, приводит телефоны к `+7XXXXXXXXXX`, отбрасывает невалидные, схлопывает дубли по телефону и отдаёт `{clients, stats}`.

Живой адрес: http://132.243.252.69:8787/

## Правила

- **Телефон.** Остаются только цифры. 11 цифр с первой 7 или 8 дают `+7` и последние 10 цифр; 10 цифр с первой 9 — номер без кода страны, к нему добавляется `+7`. Всё остальное считается невалидным и отбрасывается.
- **Дубли.** Из записей с одним телефоном остаётся та, у которой больше `amount`; при равных суммах — более поздняя по `created_at`; при полном совпадении — с большим `id`, чтобы результат не зависел от порядка заявок.
- **Статистика.** `received = unique + duplicates_merged + invalid_dropped`.
- **Идемпотентность.** Сервис без состояния: каждый запрос заново забирает заявки и считает результат детерминированно, клиенты отсортированы по телефону, поэтому повтор даёт тот же JSON.

## Эндпоинты

- `GET /` — результат синхронизации; 502, если источник недоступен или вернул не массив.
- `GET /health` — проверка живости.

## Запуск и тесты

```bash
PORT=8000 python3 app.py
python3 -m unittest -v
```

Зависимостей нет, только стандартная библиотека Python 3.9+. Тесты работают на снимке данных из `fixtures/` и не ходят в сеть. CI на GitHub Actions гоняет `ruff` и тесты на Python 3.9 и 3.12.

## Настройки и секреты

Настройки задаются переменными окружения, пример — `.env.example`: `SOURCE_URL`, `SOURCE_TIMEOUT`, `PORT`. Секретов в задаче нет; если появятся ключи, они живут только в окружении сервера, `.env` в `.gitignore`.

## Деплой

Свой сервер, systemd-юнит `deploy/bs-orders-sync.service`: сервис работает от временного пользователя без прав (`DynamicUser`), с закрытой файловой системой и ограничением памяти, и сам перезапускается при падении.
